# AutoLot

Майданчик продажу автомобілів для українського ринку — з аукціоном, живими торгами
й чатом. Портфоліо-проєкт; повне технічне завдання — у [docs/SPEC.md](docs/SPEC.md).

Задум простий: узяти звичний класифайд (AutoRia) і додати те, чим живе Cars & Bids —
торги з антиснайпінгом, публічну історію ставок і автоставку. Тому «оголошення» тут
має два різновиди: з фіксованою ціною і лот з торгами, і майже кожна частина системи
знає про обидва.

## Можливості

**Каталог і оголошення.** Пошук із трьома десятками фільтрів, сортування, пагінація ·
подання й редагування оголошення з фото · модерація з чергою і причинами відмови ·
обране · порівняння до чотирьох авто пліч-о-пліч · збережені пошуки з email-сповіщеннями
про нові збіги · історія переглядів · довідка про ринкову ціну по моделі та році.

**Аукціон.** Ставки під блокуванням рядка · автоставка (proxy bidding) · антиснайпінг ·
публічна історія ставок · автозавершення за розкладом і визначення переможця ·
живий таймер і стрічка ставок через SignalR.

**Люди.** Реєстрація email-паролем і вхід через Google · підтвердження пошти ·
відновлення пароля · публічні профілі з рейтингом · взаємні відгуки після угоди ·
приватний чат покупця з продавцем · скарги на оголошення.

**Салони.** Салон як окрема сутність із персоналом: власник запрошує менеджерів,
оголошення належать салону, а не людині, тож звільнення менеджера їх не забирає ·
публічні вітрини · верифікація в адмінці.

**Адмінка.** Черга модерації · черга скарг · верифікація салонів · керування
користувачами (бан, ролі) · показники майданчика.

**Решта.** Підписки з лімітами на віртуальному балансі (справжніх платежів немає) ·
Telegram-бот із прив'язкою акаунта одноразовим кодом і сповіщеннями · дві мови
інтерфейсу з перемикачем · темна тема · SEO: заголовки, Open Graph, `sitemap.xml`.

Чого **немає**: перевірок VIN по держреєстрах, реальних платежів, мобільного
застосунку, типів транспорту, крім легкових авто. Межі обсягу описані в
[SPEC §9](docs/SPEC.md).

## Стек

ASP.NET Core 10 (Web API, EF Core 10, SignalR, Quartz.NET) · PostgreSQL 18 ·
React 19 + Vite + TypeScript + Tailwind CSS v4 · TanStack Query.

## Структура

```
AutoLot/
├─ backend/
│  ├─ AutoLot.Domain           сутності та доменні правила; без зовнішніх залежностей
│  ├─ AutoLot.Application      сценарії, DTO, валідація, інтерфейси інфраструктури
│  ├─ AutoLot.Infrastructure   EF Core, доступ до даних, зовнішні сервіси
│  ├─ AutoLot.Api              контролери, DI, middleware, health-checks
│  └─ AutoLot.Tests            модульні тести + тести архітектури
├─ frontend/                   React + Vite + TypeScript
├─ docs/
└─ docker-compose.yml          поки лише PostgreSQL
```

Залежності спрямовані всередину: `Api → Application → Domain`,
`Infrastructure → Application → Domain`. За напрямком стежать тести в
`AutoLot.Tests/Architecture` — вони падають, якщо хтось додасть посилання
навпаки.

## Запуск

Потрібно: **.NET SDK 10** · **Node 24** · **PostgreSQL 18 на порту 5433** ·
`dotnet-ef` (`dotnet tool install --global dotnet-ef`).

### 1. База даних

Локальна служба PostgreSQL:

```bash
psql -h localhost -p 5433 -U postgres -f docs/db-setup.sql -v password='<пароль>'
```

Або через Docker (`cp .env.example .env`, задати `POSTGRES_PASSWORD`):

```bash
docker compose up -d
```

### 2. Секрети

Секрети в репозиторії не зберігаються — лише в `user-secrets`:

```bash
cd backend/AutoLot.Api

dotnet user-secrets set "ConnectionStrings:AutoLot" \
  "Host=localhost;Port=5433;Database=autolot;Username=autolot;Password=<пароль>"

# Ключ підпису JWT, щонайменше 32 символи
dotnet user-secrets set "Jwt:Key" "$(openssl rand -base64 48)"

# Перший адміністратор. Без цих двох значень сід його не створює
dotnet user-secrets set "Seed:Admin:Email" "admin@autolot.local"
dotnet user-secrets set "Seed:Admin:Password" "<пароль>"
```

Три можливості вмикаються **наявністю ключів** і без них чесно віддають помилку,
а не вдають, що працюють:

```bash
# Вхід через Google. Без цих ключів схема не реєструється взагалі,
# а /api/auth/google/start відповідає 501
dotnet user-secrets set "Authentication:Google:ClientId" "<id>"
dotnet user-secrets set "Authentication:Google:ClientSecret" "<secret>"

# Telegram-бот. Токен видає @BotFather
dotnet user-secrets set "Bots:Telegram:Token" "<токен>"
```

Redirect URI у консолі Google — `http://localhost:5080/signin-google`.

Пошта в розробці **нікуди не йде**: `SmtpEmailSender` кладе готові `.eml` у теку
`Email:DropFolder` (за замовчуванням `mail-drop` у корені). Їх видно, і жодного
SMTP-сервера не потрібно.

### 3. Міграції

```bash
dotnet ef database update \
  --project backend/AutoLot.Infrastructure \
  --startup-project backend/AutoLot.Api
```

Нова міграція:

```bash
dotnet ef migrations add <Назва> \
  --project backend/AutoLot.Infrastructure \
  --startup-project backend/AutoLot.Api \
  --output-dir Persistence/Migrations
```

### Демо-дані

У режимі розробки при першому старті створюється **200 оголошень** із фото-заглушками,
на яких намальовані марка, модель і рік. Кожне восьме оголошення — лот з торгами, з
готовою історією ставок. Вмикає це `DemoData:Enabled`: у `appsettings.Development.json`
він `true`, за замовчуванням у коді — `false`. Набір відтворюваний, бо всі випадкові
значення йдуть від одного зерна.

Продавці описані в
[demo-sellers.json](backend/AutoLot.Infrastructure/Persistence/SeedData/demo-sellers.json):
дванадцять людей, четверо з них — власники автосалонів. Оголошення такого продавця
належать САЛОНУ, а не йому особисто, тож у видачі видно і бейдж салону, і різницю між
перевіреним та неперевіреним.

**Демо-дані не псуються від часу.** Строк лота відраховується від запуску застосунку, а
не від дати наповнення бази: при кожному старті сідер знаходить торги, яким вийшов час,
і запускає їх наново з новою історією ставок. Інакше через тиждень після сіду всі
аукціони були б мертві, а вкладка «Аукціони» — порожня. Чужих даних це не торкається:
сідер упізнає свої за поштою `@autolot.local`.

## API

Повний перелік — в інтерактивній документації на `/scalar`. Нижче — карта розділів.

### Автентифікація

| Метод і шлях | Що робить |
|---|---|
| `POST /api/auth/register` | реєстрація, одразу видає токени |
| `POST /api/auth/login` | вхід за email і паролем |
| `POST /api/auth/refresh` | обмінює refresh-cookie на нову пару токенів |
| `POST /api/auth/logout` | гасить сесію і чистить cookie |
| `GET /api/auth/me` | профіль поточного користувача |
| `GET /api/auth/google/start` · `/callback` | вхід через Google |
| `POST /api/auth/forgot-password` · `reset-password` | відновлення пароля |
| `POST /api/auth/confirm-email` · `resend-confirmation` | підтвердження пошти |

Access-токен живе 15 хвилин і повертається в тілі відповіді. Refresh-токен
віддається **лише** в httpOnly cookie з областю `/api/auth`, у базі лежить
хешем і ротується при кожному оновленні: пред'явлення вже використаного токена
вважається крадіжкою і гасить усю сім'ю токенів цієї сесії.

Обмеження: 10 запитів за хвилину з однієї адреси на всі маршрути `/api/auth`,
блокування акаунта на 15 хвилин після 5 невдалих спроб входу.

## Як воно влаштоване

Далі — рішення, які не видно з переліку маршрутів, але які визначають проєкт.

### Довідники живуть у файлах, а не в коді

Географія має чотири рівні, два з них необов'язкові:
`область → район області → місто → район міста`. Київ і Севастополь районів
області не мають, райони міста є лише у великих містах.

Дані лежать у
[geography.json](backend/AutoLot.Infrastructure/Persistence/SeedData/geography.json),
[car-attributes.json](backend/AutoLot.Infrastructure/Persistence/SeedData/car-attributes.json),
[car-makes.json](backend/AutoLot.Infrastructure/Persistence/SeedData/car-makes.json)
і [plans.json](backend/AutoLot.Infrastructure/Persistence/SeedData/plans.json), а
заливаються при старті. Сід ідемпотентний: він шукає записи за сталим кодом, тож
повторний запуск нічого не дублює. **Щоб розширити довідник, достатньо дописати
записи у файл — код міняти не треба.**

Засіяно всі 27 регіонів, усі 136 районів за реформою 2020 року та 293 міста;
48 марок, 426 моделей і 70 поколінь; 14 кузовів, 8 типів пального (з гібридом,
плагін-гібридом, електро й воднем), 52 опції комплектації в п'яти розділах,
46 країн.

Кузови, палива, коробки, приводи й кольори — це `enum` у
[AutoLot.Domain.Enums](backend/AutoLot.Domain/Enums/): переліки замкнені, тож
компілятор стежить, щоб ніхто не вписав неіснуючий тип. У базі лежать лише їхні
назви для показу, у таблиці `enum_translations`. Марки, моделі й покоління
навпаки живуть у таблицях, бо їх сотні й вони змінюються.

### Каталог

`GET /api/catalog` показує **лише активні** оголошення: це межа видимості, а не
фільтр, який можна зняти параметром.

Фільтри: марка, модель, покоління · ціна з валютою · рік, пробіг, об'єм,
потужність · кузов, паливо, КПП, привід, колір · новий чи вживаний · ДТП,
розмитнення, наявність в Україні, країна пригону · область і місто · тип
продавця · опції комплектації · наявність фото.

Набори значень працюють як **«або»** (седан + універсал = обидва типи), опції
комплектації — як **«і»** (підігрів + парктроніки = авто, де є обидва). Ціна
порівнюється в гривні, тож «до 5000 USD» знаходить і гривневі оголошення.
Розмір сторінки обмежений 60 — інакше один запит витягнув би всю базу.

Сортування: найновіші, дешевші, дорожчі, менший пробіг, свіжіший рік. У кожен
порядок доданий ключ за `Id`, інакше оголошення з однаковою ціною могли б
з'їхати між сторінками й показатися двічі.

Стан фільтрів живе в адресному рядку, а не тільки в пам'яті сторінки: посиланням
на пошук можна поділитися, і кнопка «назад» повертає попередню видачу.

### Життєвий цикл оголошення

`Draft → PendingModeration → Active → (Sold | Archived)`, з поверненням у
`Rejected` і повторним поданням. Переходи описані методами самої сутності
[Listing](backend/AutoLot.Domain/Listings/Listing.cs), а не розкидані по сервісах.

Чуже неопубліковане оголошення віддає `404`, а не `403` — інакше за кодом
відповіді можна було б перебирати чужі чернетки. Ліміт активних оголошень —
властивість тарифного плану (базовий: 5); чернеток може бути скільки завгодно,
бо місця у видачі вони не займають.

**Статус зберігається в базі рядком** (`'Active'`), а не числом. `UPDATE listings
SET status = 2` запише літерал «2» і тихо зламає запис — жоден запит його потім
не знайде.

### Фото

Завантажене зображення ніколи не зберігається таким, як прийшло. Тип файла
визначається за вмістом, а не за розширенням; зображення перекодовується в JPEG,
що зрізає EXIF із координатами зйомки та будь-який вкладений вміст; зберігаються
дві копії — до 1920 пікселів по довшій стороні та мініатюра 400 для списків.
Ліміти: 10 МБ на файл, 20 фото на оголошення. Файли лежать поза `wwwroot` і
роздаються за `/media`; тека `uploads/` у репозиторій не потрапляє. Перше фото
стає головним само, а якщо головне видалити — головним стане наступне.

### Аукціон

Ставка приймається під блокуванням рядка аукціону, тож дві одночасні ставки не
можуть обидві виграти. Крок ставки залежить від поточної ціни й валюти —
[BidStep](backend/AutoLot.Domain/Auctions/BidStep.cs).

**Автоставка.** Людина називає максимум, а система піднімає ціну за неї рівно
настільки, щоб перебити суперника — не одразу до максимуму.

**Антиснайпінг.** Ставка в останню хвилину відсуває фінал ще на хвилину, і так
доки ставки не вщухнуть. Ліміту продовжень немає **навмисно**: снайперові
досить було б дочекатися, поки ліміт вичерпається.

Завершення веде задача Quartz
([CloseAuctionJob](backend/AutoLot.Infrastructure/Auctions/CloseAuctionJob.cs)).
Після перезапуску застосунку розклад відновлюється з бази — інакше лоти, що мали
закритися під час простою, висіли б вічно.

### Салони

Спокуслива помилка — зробити продавцем салон замість людини: тоді
`Listing.SellerId` перестає бути людиною і кожна перевірка прав ламається. Тому
поля два: `SellerId` — хто фізично подав, `DealershipId` — чий це лот (порожній у
приватної особи). Правило власності: «моє, якщо я подав **або** я менеджер салону,
якому воно належить». Ліміти з підписки чіпляються до салону, а не до людини.

### Безпека й журнал

Пароль, токен і рядок підключення не потрапляють у журнал ніколи. Кожен запит має
наскрізний ідентифікатор, за яким його видно від входу до бази. Події
пронумеровані за розділами (вхід, оголошення, відгуки, салони, боти) — діапазони
описані в [SPEC §8](docs/SPEC.md).

### Дві мови

Словники інтерфейсу — два плоскі об'єкти в
[messages.ts](frontend/src/i18n/messages.ts); українська задає тип, тож
англійська **зобов'язана** покрити всі ключі, інакше не збереться. Готової
бібліотеки немає навмисно: i18next важить більше за всю теку локалізації й дає
те, чого проєкту не треба.

Повідомлення сервера (помилки валідації та доменних правил) не збираються
рядками на місці: код кидає **код повідомлення**, а текст підставляється на межі
застосунку за `Accept-Language`. Підстановки на кшталт `{email}` їдуть через
`Exception.Data`.

Множина рахується через `Intl.PluralRules` — в українській форм чотири, і
писати їх вручну означало б помилятися.

### Фронтенд

**Access-токен живе лише в пам'яті вкладки, не в `localStorage`:** те, що лежить
у сховищі, читає будь-який скрипт на сторінці, тож одна вразливість у сторонній
бібліотеці віддала б чужий доступ надовго. Після перезавантаження сесія
поновлюється сама — з httpOnly cookie, якої JavaScript не бачить узагалі.

Відповідь `401` на робочій сесії — звичайна річ, бо токен живе 15 хвилин:
[client.ts](frontend/src/api/client.ts) мовчки поновлює сесію й повторює запит
один раз. Поновлення одне на всіх одночасних запитів — інакше три паралельні
спроби зіпсували б одна одну, бо refresh-токен ротується.

Кожна сторінка вантажиться окремим файлом
([App.tsx](frontend/src/App.tsx)): каталог іде одразу, решта — коли на неї
переходять, а файл сторінки авто починає вантажитися вже на наведення курсора.
Бібліотеки відокремлені від нашого коду, тож правка в коді не змушує браузер
качати React заново.

Довідники — кузови, пальне, коробки, марки, міста — фронтенд не тримає в себе, а
тягне з API. Оголошення приходить із сирим значенням (`fuelType: "Petrol"`), бо
саме його треба надіслати назад у фільтрі; назву для показу дає
`/api/cars/attributes`, уже перекладену сервером.

Оформлення: холодний нейтральний фон, приглушений бірюзовий акцент для дій,
Bahnschrift для заголовків. Бурштиновий колір зарезервований **виключно** для
лотів з торгами — оголошення з фіксованою ціною ним ніколи не фарбується.
Палітра оголошена токенами Tailwind у [index.css](frontend/src/index.css), тож
відтінок міняється в одному місці; темна тема перевизначає ті самі токени.

### Пошукові системи

Пошуковий робот не виконує JavaScript, тож заголовок і опис конкретного авто
він у React-застосунку не побачить. Тому коли сторінку роздає бекенд
([SpaHosting.cs](backend/AutoLot.Api/Extensions/SpaHosting.cs)), він підставляє
у відповідь теги саме цього оголошення — з ціною, описом і фото.
